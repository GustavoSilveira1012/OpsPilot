# Sprint 1 · OPS-002 · PostgreSQL and Prisma foundation

## Goal

Add a versioned PostgreSQL schema and Prisma access layer for organization-scoped incident coordination.

## Included

- PostgreSQL 18.6 local development service through Docker Compose.
- Prisma ORM 7.10.0 using the supported ESM client generator and PostgreSQL driver adapter.
- Initial migration for users, organizations, memberships, services, service ownership, incidents, active incident responders, and incident timeline events.
- Composite tenant foreign keys and indexes for organization-scoped access patterns.
- API Prisma client lifecycle provider and schema validation in CI.
- Windows PowerShell database setup and migration instructions.

## Data ownership

`users.id` is the UUID supplied by Supabase Auth. This migration stores profile and lifecycle metadata only; authentication and password credentials remain with Supabase Auth. Organization membership and API authorization are implemented in the following tasks.

## Validation commands

```powershell
pnpm db:validate
pnpm db:generate
pnpm --filter @opspilot/api db:migrate:dev --name ops002_initial_schema
pnpm lint
pnpm typecheck
pnpm build
```

The CI workflow validates the Prisma schema and runs the monorepo quality gates.
